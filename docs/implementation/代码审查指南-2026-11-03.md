| `software/app/tests/run.mjs` | 9 项测试 |

### 5.2 审查要点（安全相关）

- [ ] **`stop` 调用点**：原来的 `act === "stop"` 分支抽成了 `onStop({ fromControl })`。顺序仍然是先 `emit(STOP)`，之后才做触感反馈和切页面，不会因为 UI 操作耽误停机。
- [ ] **按住 800ms 停止**发的是 `NlCmd.STOP`，会触发停机闩锁。这是有意的失效安全设计：手指误停住，结果是停下，而不是继续。但在 Nascent 固件上，停下后要按 BOOT 键才能恢复，体验上请确认能接受。
- [ ] **松手才提交**：`attachGestureSurface` 里，`pointermove` 只调 `onPreview`，`pointerup` 才调 `onCommit`，`pointercancel` 会回滚预览，不发任何指令。
- [ ] `setPointerCapture` 外面包了 try。合成事件或不支持的环境下它会抛错，原来会让整个处理函数中断。
- [ ] **安抚页**只在 `emit(STOP)` 返回 `null`（也就是发送成功）、并且是从控制页发起时才出现；离开控制页时 `render()` 会调用 `leaveAftercare()`。

### 5.3 审查要点（其他）

- [ ] **原生桥暴露面**：`NascentShell.setKeepScreenOn` 对 WebView 里加载的任何页面都可调用。这个壳只加载用户自己配置的站点，和已有的 `openConnectionSettings` 风险同级。
- [ ] **耗电**：只要连着设备，在任何页面都会保持常亮（`shouldKeepScreenOn`）。理由是熄屏后脚本被挂起，设备链路会被判为断连。产品上如果觉得太费电，可以收窄到只在亲密时刻的页面保持常亮。
- [ ] 雨声用 Web Audio 在本地合成，不走网络；`setAftercareSound(false)` 会 `stop` 音源并 `close` 音频上下文。
- [ ] **Android 未构建**，没有真机验证。

### 6.2 审查要点（安全相关，**必须项目负责人看**）

- [ ] **新增了一个连续调档来源**。`FrequencyPlayer` 每步调用 `sendCommand(new BleDownlink({cmd: SET_LEVEL, level}))`，**没有传 `automatic: true`**。理由是播放由用户主动发起，相当于原机内置的模式；而没有传感器时，`automatic` 永远会被「使用状态 unknown」挡掉。这是一个产品和安全口径上的决定，需要拍板。
- [ ] **频率步长下限是 500ms**（`FREQ_STEP_MS_MIN`），所以 BLE 写入最高 2 次/秒。
- [ ] **档位上限**由 `normalizeFrequency` 限在 1..9，Governor 还会再检查一次越界。精选频率最高 6 档。
- [ ] **会停止播放的情况**，请逐条核对：
  - 按停止按钮：`act === "stop"` 先 `freqPlayer.halt()`，再 `emit(STOP)`；
  - 点「停下」：`toggleFrequency` 调 `haltFrequency({sendStop: true})`；
  - 离开频率广场：`render()` 里 `if (freqPlayer.playing && !(tab === "intimacy" && page === "frequency")) haltFrequency({sendStop: true})`；
  - 切到后台：新增的 `visibilitychange` 监听调 `haltFrequency({sendStop: true})`；
  - 设备断连：`patchTelemetry()` 里 `freqPlayer.halt(...)`（这时发 stop 也发不出去，所以不发）；
  - 任何一次被拒：`FrequencyPlayer._tick` 拿到 `reason` 就调 `halt(reason)`，不重试。
- [ ] **会不会死循环**：`onHalt` 只在当前页是频率广场时才 `render()`，而 `render()` 只在离开频率广场时才 halt，两者不会互相触发。
- [ ] **定时器的坑（已修）**：默认的 `setTimer` 必须写成 `(fn, ms) => setTimeout(fn, ms)`。如果直接把 `setTimeout` 当成对象方法调用，浏览器会抛 `Illegal invocation`，而 Node 不会，单测发现不了。请确认没有被改回去。
- [ ] 进入频率广场时，和自我控制一样先 `SET_MODE free`（`act === "sub"` 里的 `manualPage`）。

### 6.3 审查要点（输入与 XSS）

- [ ] **分享码解码**：`decodeFrequency` 先找 `NLF1:` 前缀，只截取 `[A-Za-z0-9_-]+`，再 base64url 解码、`JSON.parse`；档位串必须匹配 `^[1-9]+$`，最后过 `normalizeFrequency`（名字截到 16 字、标签最多 3 个且每个最多 6 字、步长 500–3000ms、长度 4–32）。
- [ ] **本地存储被篡改**：`FrequencyLibrary` 读取时对每一项都过一遍 `normalizeFrequency`，不合法的直接丢弃。
- [ ] **转义**：`frequencyCard` 里的名字、标签、id 都经过 `escapeHtml`；分享弹窗里的分享码也是。`patchFrequencyStep` 查询 DOM 时用了 `CSS.escape(id)`。

### 6.4 审查要点（其他）

- [ ] 「和 AI 聊聊自己」只是去掉了入口，`renderInsight` 和 `#/records/<id>/insight` 路由还在，直接打开 URL 仍能进去。属于死代码，待删。

```js
window.__sent = [];
let level = 0;
const up = () => window.__nascentNativeOnUplink?.(JSON.stringify({
  ts: Date.now(), press_l: 0, press_r: 0, accel: [0, 0, 1], gyro: [0, 0, 0],
  insert_state: "unknown", mode: "free", level, alert: "none",
}));
window.NascentNative = {
  connect() {
    setTimeout(() => {
      window.__nascentNativeConnect.resolve({ proto: "0.3.0-demo", token: "t" });
      setInterval(up, 100);
    }, 50);
  },
  send(json) {
    const b = JSON.parse(json);
    window.__sent.push(`${b.cmd}:${b.level ?? ""}`);
    if (b.cmd === "set_level") level = b.level;
    if (b.cmd === "stop") level = 0;
    return "";
  },
  disconnect() {},
};
```
